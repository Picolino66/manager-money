# T-035 — Repositório Supabase, autenticação e guarda de rota (CLIENT-006/007/008)

- **Prioridade:** P0 · **Sprint:** S7 · **Pontos:** 8

## Spec relacionada
[SPEC-022](../../specs/SPEC-022-client-web-mvp.md) · plano: [client-web-plan](../../docs/architecture/client-web-plan.md)

## Objetivo
Ler e gravar direto no Supabase pelo núcleo; entrar, criar conta, sair; sessão expirada.

## Escopo
`client/src/infrastructure`, `client/src/store`, `client/src/features/auth`, guarda de rota.

## Fora de escopo
Sync, outbox, cache local.

## Critérios de aceite
Leitura completa paginada; upsert só dos `dirty` na ordem de dependência; falha não altera o estado; `23505` tratado; sessão persiste no reload; refresh falho → login com aviso.

## Agente responsável
[web-engineer](../../agents/web-engineer.md)

## Skills necessárias
autonomous-software-orchestrator, react-router-specialist

## Evidências de conclusão
- `infrastructure/remote.ts` (`SupabaseGateway`: linhas vivas paginadas de 1000, upsert por `user_id`/`user_id,id`,
  erros via `mapSupabaseError` do core), `repository.ts` (`loadUserState` + recálculo do saldo em memória +
  `markAllClean`; `saveChanges` com `collectDirty` na ordem de `SYNC_TABLES`, `SaveError{code, partial}`).
- `auth.ts` (`SupabaseAuthGateway`, `mapAuthError`), `session.store` (sessão persistida, saída não pedida → aviso),
  `data.store.run` (recarrega → caso de uso → grava; falha mantém o estado; `23505` e parcial recarregam;
  `auth` → refresh → senão login com aviso), `RequireAuth`.
- Testes: repositório (ordem, só alterados, `closed` antes de `active` com índice único simulado, parcial),
  remote (paginação, filtros, erros), auth (sem e-mail/token nos logs), stores (todos os caminhos de erro).
