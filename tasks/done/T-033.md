# T-033 — Extrair `packages/core` com npm workspaces (CLIENT-003)

- **Prioridade:** P0 · **Sprint:** S7 · **Pontos:** 8

## Spec relacionada
[SPEC-022](../../specs/SPEC-022-client-web-mvp.md) · plano: [client-web-plan](../../docs/architecture/client-web-plan.md)

## Objetivo
Fonte única das regras financeiras para app e web, sem mudar o comportamento do app (ADR-022).

## Escopo
Workspaces na raiz; `packages/core` (domain, application, utils, contract, legal) com testes em Vitest; imports do app; `collectDirty`/`acknowledge`/`mapSupabaseError`/`legacyIncomeSources` no core; CI do app.

## Fora de escopo
Qualquer mudança de regra ou de comportamento do app; EAS build (manual, pelo dono do produto).

## Critérios de aceite
Em `app/`: `verify` verde (lint 0 avisos, typecheck, cobertura ≥ 80%), `npx expo-doctor`, `npx expo export -p android`; core com cobertura ≥ 80%.

## Agente responsável
[mobile-engineer](../../agents/mobile-engineer.md)

## Skills necessárias
autonomous-software-orchestrator, react-native-expo-architect

## Evidências de conclusão

cobertura 96,57% statements / 88,87% branches / 97,25% linhas.

`packages/core/src/{domain,application,utils,legal,contract}`; `collectDirty`/`acknowledge` (de
`sync-engine.ts`) → `contract/dirty.ts` (+ `markAllClean` para o web); `mapSupabaseError` → `contract/errors.ts`;
`legacyIncomeSources` → `contract/mappers.ts`. 43 arquivos do app com imports reescritos por script
(`@manager-money/core/<caminho>`), 14 reformatados pelo Prettier por causa disso. Lockfile da raiz
derivado do `app/package-lock.json`: **0 versões alteradas, 0 removidas**, 50 pacotes novos (ferramentas do core).
